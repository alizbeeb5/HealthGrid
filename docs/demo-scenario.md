# First end-to-end demonstration
Use three clearly fictional hospitals and one service to demonstrate the broader
configurable platform. Do not present scenario assumptions as validated forecasts.

1. Import facility and resource observations with timestamps and units.
2. Calculate usable capacity from agreed service requirements.
3. Forecast demand and show uncertainty and the limiting resource.
4. Activate crisis mode: record a sudden service outage and demand surge at Demo
   Hospital A. Confirm proposed incident inputs and save a versioned disruption
   scenario without changing reported observations.
5. Compare feasible redistribution and investment alternatives under a budget.
6. Display capacity, cost, unmet demand, time to effect, assumptions, solver status
   and an approval step. Add a follow-up report to compare with the expected result.

Measure time to first feasible response on this dataset. Do not claim a guaranteed
emergency response time. Distinguish incident assumptions from historical forecasts.
See `product-scope.md` for the full workflow and limits of the demonstration.

Each feature is still to be implemented. The example scenario only fixes the
structure of shared demo identifiers and assumptions for discussion.
